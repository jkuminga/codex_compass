# 저장 가치 평가

점수는 “유용해 보이는가”를 정량화하는 보조 수단이다. 강제 제외와 기존 기억 비교가 점수보다 우선한다.

## 1. 강제 제외

하나라도 해당하면 총점과 무관하게 `reject`한다.

- 비밀정보, 인증정보, 개인정보
- 현재 Run·진행률·임시 경로처럼 State DB나 Trace가 담당할 일회성 상태
- 근거 없이 가능성만 제시한 추측
- 출처와 대상을 잃으면 이해할 수 없는 문장 조각
- 기존 기억과 내용·근거가 완전히 같은 중복

## 2. 10점 평가

### 재사용 가능성 · 0~3점

- `0`: 현재 요청에서만 필요하다.
- `1`: 매우 좁은 한 상황에서 다시 쓸 수 있다.
- `2`: 같은 기능이나 기술의 다른 Run에서도 다시 쓸 수 있다.
- `3`: 여러 세션·기능에서 반복적으로 판단이나 작업을 바꾼다.

### 장기 유효성 · 0~2점

- `0`: 곧 바뀌며 유효 시점·출처도 없다.
- `1`: 버전·파일·정책에 따라 바뀌지만 적용 조건, 날짜 또는 출처가 명확하다.
- `2`: 의도적인 설계 변경 전까지 유지되는 원리·결정·검증 결과다.

### 독립적인 유용성 · 0~2점

- `0`: 원래 대화 없이는 의미를 알 수 없다.
- `1`: 이해는 되지만 적용 대상이나 결과가 일부 빠져 있다.
- `2`: 이 기억만 읽어도 적용 조건과 의미를 이해하고 판단·행동·오류 예방에 사용할 수 있다.

### 근거 명확성 · 0~2점

- `0`: 느낌, 막연한 우려, 검증되지 않은 가설이다.
- `1`: 합리적인 설명이나 단일 간접 근거가 있지만 반례·위치·과정이 불완전하다.
- `2`: 다른 에이전트가 같은 자료를 보고 같은 결론에 도달할 수 있다.

2점 근거는 코드와 테스트에 한정되지 않는다. 다음을 동등하게 인정한다.

- 코드 위치, 테스트, 명령 결과, 오류 로그
- 서로 충돌하는 문서의 정확한 위치와 내용
- 처리할 수 없는 사례를 보여주는 구체적인 반례
- 입력부터 모순된 결과까지 이어지는 단계별 논증
- 스키마로 표현할 수 없는 상태를 재현한 흐름
- 사용자가 명시적으로 확정한 설계 결정이나 장기 선호

기억 종류별로 적합한 근거가 다르다.

- `problem`, `error`: 재현 흐름·로그·테스트 또는 명확한 문서·설계 모순
- `solution`, `fix`: 실행 검증 또는 논리적으로 완결된 해결 결과
- `project`, `workflow`: 사용자 합의, 설계 기록, 실제 운영 흐름
- `command`: 실행 결과와 사용 조건
- `technology`, `file_context`: 코드·공식 문서·버전·파일 위치
- `conversation`: 사용자의 직접 발언

### 프로젝트 영향도 · 0~1점

- `0`: 국소적인 편의 정보다.
- `1`: 아키텍처·안전성·반복 작업을 바꾸거나 의미 있는 재작업을 예방한다.

## 3. 판정

- `7~10점`: 저장 대상. 기존 기억과 비교해 create 또는 merge를 결정한다.
- `0~6점`: reject한다.

경계 점수를 임의로 올리지 않는다. 후보 생성 단계에서 이미 한 번 선별됐으므로 finalize는 재현율보다 정밀도를 우선한다.
