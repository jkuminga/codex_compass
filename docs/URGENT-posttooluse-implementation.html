PostToolUse·Artifact 기록 전략

start_work()와 finish_work()의 수명주기 처리는 전용 PostToolUse가 맡는다. 테스트·lint·빌드·커밋 같은 일반 도구 결과는 전체 셸을 자동 분석하지 않고, 결과를 직접 본 Codex가 의미를 판단해 record_artifact() MCP를 명시적으로 호출한다.

결론흐름용어기록 기준실행 URI책임 분리Agent 지침구현 순서위험·비범위

결정

PostToolUse의 책임을 좁히고, 의미 판단은 이미 명령과 결과를 읽고 있는 Codex에게 둔다.

전용 Hook 2개만 유지한다.

start_work() 성공 뒤에는 Runtime Binding 저장과 장기 기억 Recall을 수행한다. finish_work() 성공 뒤에는 해당 Run의 Runtime Binding을 제거한다.

start_work lifecyclefinish_work lifecycleno shell parser

일반 결과는 Codex가 저장한다.

Codex는 테스트·lint·빌드·커밋 등의 실행 결과가 현재 Run을 검증하는 의미 있는 결과인지 판단한다. 저장 가치가 있으면 record_artifact()를 한 번 더 호출하고, 아니면 아무것도 기록하지 않는다.

두 갈래 처리 흐름

수명주기 자동화와 일반 작업 결과 기록을 분리한다.

핵심 용어

이 문서에서 반복되는 객체와 함수의 뜻이다.

키워드쉬운 설명책임
Artifact현재 Run에서 실제로 얻은 검증 가능한 결과. 테스트 결과, 빌드 결과, 생성된 커밋 등이 예다.원문 전체가 아니라 종류·상태·짧은 요약·참조 위치만 보관한다.
record_artifact()Codex가 의미 있는 결과를 발견했을 때 Artifact를 상태 저장소에 넣는 MCP 도구.입력 검증 뒤 state_store.py의 DB 함수를 호출한다.
Runtime Binding현재 세션·Turn이 어느 WorkItem과 Run을 수행 중인지 가리키는 작은 로컬 JSON 포인터.Artifact가 엉뚱한 Run에 연결되지 않도록 현재 작업을 식별한다.
PostToolUse도구 호출이 끝난 직후 실행되는 기계적인 Hook.이 설계에서는 작업 시작·종료 수명주기만 자동 처리한다.

Codex의 Artifact 기록 기준

종료 코드 하나가 아니라 실행 목적과 실제 결과를 함께 본다.

기록한다

  • 테스트·lint·빌드가 실제로 끝났고 성공 또는 실패가 확인됨
  • Git 커밋이 실제로 생성되어 커밋 ID를 확인함
  • 현재 Run의 완료 여부를 검증하는 파일·보고서가 생성됨
  • 실패 결과도 이후 수정과 재검증에 의미가 있음

기록하지 않는다

  • pytest --collect-only, 도움말, 버전 조회, dry-run
  • 일반 파일 조회, 진행 로그, 단순 상태 확인
  • 아직 실행 중이거나 결과가 모호한 background 명령
  • 같은 의미의 중복 결과, 비밀정보, stdout·stderr 전문
중요: Artifact 저장과 Acceptance Criterion 완료는 다르다. Codex는 Artifact를 저장한 뒤, 그 결과가 특정 완료 기준의 Evidence라면 별도로 verify_criterion()을 호출한다.

반복 실행 결과의 URI 규칙

같은 명령을 다시 실행해 결과가 달라져도 각각 독립된 Artifact로 보존한다.

테스트·lint·빌드

반복 실행되는 결과의 uri에는 실행을 시작한 UTC 시각을 YYYYMMDDTHHMMSSZ 형식으로 붙인다. uri는 Artifact가 어떤 실행에서 나온 결과인지 구분하는 식별표다.

command:pytest:20260827T160500Z  → failed
command:pytest:20260827T160830Z  → passed

command:ruff-check:20260827T161010Z
command:npm-build:20260827T161245Z

같은 초에 같은 명령을 두 번 시작하는 충돌이 실제로 생기면 UTC 시각 뒤에 짧은 무작위 접미사를 추가한다.

파일·커밋

파일과 커밋에는 이미 실제 대상을 가리키는 안정적인 식별자가 있으므로 실행 시각을 붙이지 않는다.

file:docs/report.html
git:8f41c2e9...
  • 파일 Artifact: 저장소 상대 경로 사용
  • 커밋 Artifact: 실제 Git commit SHA 사용
  • 같은 파일의 새 버전을 별도 결과로 보존해야 하면 Git commit SHA나 Trace 참조를 사용
record_artifact() 검증: test_run·lint_run·build_run 종류는 command:<명령군>:<UTC 시각> 형식인지 MCP 입력 단계에서 확인한다. 형식이 잘못되면 DB에 저장하지 않고 Codex가 올바른 URI로 다시 호출하도록 오류를 반환한다.

책임 분리

추론이 필요한 판단과 기계적인 저장을 섞지 않는다.

주체하는 일하지 않는 일
전용 PostToolUsestart_work() 뒤 Binding 저장·Recall, finish_work() 뒤 정확한 Binding 삭제일반 셸 명령 분석, 테스트 의미 판정, Artifact 자동 생성
Codex일반 도구 결과의 의미·종류·상태를 판단하고 필요할 때 record_artifact() 호출원문 로그 전체 저장, 불완전 결과 추측, 단순 조회 결과 남발
MCP·DB 계층Run과 입력을 검증하고 Artifact를 원자적으로 저장하며 DB 제약을 적용자연어 결과의 의미 추론, 어떤 Criterion인지 자의적으로 선택
향후 Stop 단계필수 Artifact·Evidence·Run 종료 누락을 마지막에 점검이번 구현 범위에는 포함하지 않음

AGENTS.md에 넣을 짧은 지침

일반 PostToolUse 대신 매 작업에서 Codex가 따라야 할 행동을 한 문단으로 고정한다.

일반 도구 실행 후 그 결과가 현재 Run의 검증 가능한 산출물이라면
즉시 record_artifact()를 호출한다. 테스트·lint·빌드·커밋은 실제 실행이
끝났는지와 성공·실패 결과를 확인한 뒤 저장한다. 반복 실행되는 테스트·lint·
빌드 URI에는 실행 시작 UTC 시각을 붙인다. 목록 조회·도움말·dry-run·
불완전 실행·중복 결과는 저장하지 않는다. Artifact가 완료 기준의 근거라면
별도로 verify_criterion()으로 Evidence를 연결한다.

이 문서는 지침의 확정안만 정의한다. 실제 AGENTS.md 수정은 PostToolUse 전략 구현 작업에서 함께 수행한다.

구현 순서

새 범용 Hook을 만들지 않고 기존 경계를 이용한다.

01 · INSTRUCTION

AGENTS.md에 Artifact 판단·기록 및 반복 실행 URI 지침을 짧게 추가한다.

02 · LIFECYCLE

.codex/hooks.json은 start_work·finish_work 전용 PostToolUse만 유지한다.

03 · MCP

record_artifact()가 활성 Run과 실행 Artifact의 UTC 시각 URI 형식을 검증하도록 보강한다.

04 · VERIFY

실패 후 성공 재실행, 잘못된 URI, 파일·커밋 URI와 수명주기 회귀 사례를 테스트한다.

위험과 명시적 비범위

구조는 단순해지지만 Agent 지침 준수 여부는 나중에 보완할 수 있다.

항목현재 대응
Codex가 저장을 잊음짧고 명시적인 AGENTS 지침을 사용한다. 향후 Stop 단계가 누락을 알려주는 보조 장치가 된다.
재실행 결과가 중복으로 오인됨테스트·lint·빌드는 실행 시작 UTC 시각이 포함된 새 URI를 사용한다. 똑같은 URI의 재전송만 DB의 UNIQUE(run_id, kind, uri) 제약이 막는다.
잘못된 의미 판정종료 코드뿐 아니라 명령 목적과 결과를 함께 보고, Criterion Evidence 연결은 별도 판단으로 둔다.
토큰 소비의미 있는 결과에만 짧은 MCP 호출을 한 번 추가하고 긴 원본 출력을 다시 전달하지 않는다.

이번에 만들지 않는 것

  • 일반 Bash·exec_command용 PostToolUse matcher
  • tool_input.cmd 자동 파서와 옵션별 명령 분류표
  • ArtifactProposal 중간 객체와 명령 해시 URI
  • ensure_artifact() 전용 자동 기록 함수

여전히 하지 않는 것

  • Hook에서 테스트·lint·빌드를 다시 실행
  • Artifact만 보고 Criterion·WorkItem 자동 완료
  • stdout·stderr 전문이나 비밀정보 저장
  • 이번 단계에서 OTel·Trace와 Stop Finalize 구현
